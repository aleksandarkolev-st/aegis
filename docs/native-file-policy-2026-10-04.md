# Native command diagnostics and file-tool discovery

The current coding trial exposed an expensive successful repair: JSON Patch passed all seven independent grader cases after 800 seconds, 68 measured attempts and 442,174 reported tokens. The agent activated only the PowerShell schema and repeatedly read source through shell output and artifact inspections. A faulty agent-created regression expected numeric object keys to follow array-index restrictions; the agent eventually corrected its test. The runtime recorded no uncertain effects or repeated dispatch IDs. Correct completion does not erase that inefficient behavior.

Repository file-tool guidance now appears whenever workspace reading is granted, including before any file tool has been activated. It directs the model to discover the structured read/read_batch tools, discover write/patch for requested changes, and use shell tools for commands. It explicitly preserves exploration-only requests without requiring edits and adds no read, turn or token cap.

Failed or timed-out native command results map stderr before stdout within the existing shared character allowance. A long source dump therefore cannot hide its failure diagnostic. The original artifact remains available, mapping stays bounded, and an error cannot become successful completion proof.
