## Lessons from other agents

[Codex agent security](https://learn.chatgpt.com/docs/agent-approvals-security) separates sandbox enforcement from approvals. Its network destination rules require the proxy to be enabled. The lesson for Aegis is to keep tool grants, execution isolation and evidence validation explicit. Aegis's trusted host tools intentionally cross the container boundary; granting them is not equivalent to container isolation. This audit does not establish a Codex security defect.

[Claude Code checkpointing](https://code.claude.com/docs/en/checkpointing) documents that Bash file changes cannot be rewound through its file-edit checkpoints. Aegis's conservative command invalidation and freshness tests address proof after changes; they do not provide universal rollback for host commands. Its obligation ledger must remain independent of model-written summaries.

[Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode) documents queued input and optional model-generated prompt suggestions. Aegis's persistent input follows that useful interaction pattern, while its keyboard tips are deterministic and make no model requests. [OpenAI reasoning documentation](https://developers.openai.com/api/docs/guides/reasoning) distinguishes public reasoning summaries from internal reasoning; the new activity stream follows that distinction.

## Long-task research applied to this audit

[OpenAI's long-horizon Codex experiment](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex) describes durable specifications, milestone plans, execution instructions and continuous validation. It explicitly characterizes its result as imperfect and not production ready. Aegis's corresponding checks are immutable task/obligation storage, historical plan progress, current final evidence and configured acceptance. The milestone fix preserves useful history without allowing it to certify changed final code.

[Anthropic's long-running application harness study](https://www.anthropic.com/engineering/harness-design-long-running-apps) reports context drift and overly generous self-evaluation, including superficial QA. It also shows that context-reset scaffolding became unnecessary with a newer model. The lesson applied here is to require observable acceptance outcomes and test actual terminal interaction, while measuring scaffolding overhead. An extra model's approval would not replace the frozen grader; this audit adds no evaluator agent or unconditional context reset.

[Anthropic's Managed Agents architecture](https://www.anthropic.com/engineering/managed-agents) separates durable sessions from harnesses and execution environments, and describes storing history outside the context window. Aegis already separates its host-side SQLite/artifact record from containerized commands. The question-archive regression demonstrates why durable state projections must survive transcript compaction. Scoped container checks exclude runtime metadata; trusted host capabilities still have their separately documented authority. These are design lessons and tested Aegis boundaries, not proof that Aegis is safer or more capable than either product.
