# Direct provider transition

The user requires Aegis to own its agent loop and use ChatGPT/Grok login without starting Codex or Grok Build. A smaller nested-CLI prompt is not the requested solution. Claude is pending at the user's request; custom OpenAI-compatible HTTP support remains required.

## Current state

Normal `src/model.rs` dispatch uses Aegis-owned sign-in/refresh and `src/direct.rs`: ChatGPT Responses SSE or Grok chat completions. Native provider subprocesses, native usage estimation and automatic CLI installation/fallback have been removed from execution, login, catalog discovery and evaluation preparation. Custom OpenAI-compatible HTTP remains supported. Requests carry only Aegis instructions, bounded state and the six-action schema. Production provider destinations are fixed, not taken from workspace configuration. Owned remote model catalogs are connected below. Fresh account verification, remaining fixture migration and full interactive installed verification are not all finished.

**Latest installed verification (2026-09-27):** source `3d53dbf` passed 181 Linux library checks (two explicit live diagnostics ignored), 24 selected integrations and 12 Node tests in a network-disabled source-only container. Its rebuilt Windows npm package passed offline private installation and setup-decline checks, then replaced the user's older global installation with approval. The installed command reports `aegis 0.1.0`; its native SHA256 matches the release/private bundle: `0664ecc429640917ead4515cbe2deff6488714918ea469d7822b8a3cfc44a366`. This is not full regression coverage, animation-quality or fresh owned-account inference proof, and nothing was published. Earlier installation/adapter status entries below are historical, not current-state claims.

Credential objects have no Debug or serialization implementation. Explicit saved-session reads are bounded to 1 MiB, regular-file checked, provider/account bound and read-only. They do not copy refresh tokens, mutate native credentials, select an arbitrary Grok account, or silently substitute an API key. They are not a replacement for Aegis-owned browser login, secure storage or refresh.

ChatGPT requires an explicit selected account. Grok's source-defined `X-XAI-Token-Auth` value selects its user-token authentication route; Aegis sends its own client identifier and User-Agent, not an official CLI User-Agent. HTTP 403 is a refusal, not an invitation to spoof another client or bypass access controls. Source-visible protocols do not guarantee third-party entitlement or stable hosted-service compatibility.

Only completed responses are accepted. Truncated/failed/refused responses, duplicate completions and unexpected native tool calls fail closed. Credentials echoed into assistant text are redacted before action parsing. Reported input/output/cache usage is preserved without subtracting bootstrap or cached tokens; missing usage stays unknown, never a zero-cost claim or character-based estimate. Redirects are disabled; connection, body size, interruption and timeout checks precede acceptance.

## Owned sign-in storage foundation

`src/auth_store.rs` adds bounded, provider-bound atomic storage at the user's `.aegis/auth` directory. Windows uses current-user DPAPI with provider-specific entropy, no machine-wide protection and no crypto prompt. Unix currently uses owner-only 0700 directories / 0600 files: **the Unix file contents are plaintext, not encrypted or keyring-backed**. Linked/reparse ancestors and credential files, malformed protection headers, oversized files and cross-provider copies are rejected. Expired sessions may be loaded for future refresh, but cannot produce request credentials. Errors do not include credential values; session structures have no Debug implementation.

## Owned device authentication and refresh core

`src/oauth.rs` implements two-phase device authentication for ChatGPT and Grok. The caller presents the verification link/code and controls polling/cancellation; this module does not open a browser, start a CLI or log the code. Fixed provider origins, no redirects, bounded declared/chunked JSON bodies, provider-specific protocol encoding and Aegis client identity are enforced. Grok requests a narrower six-scope set without remote conversation/workspace read/write scopes; real fresh-login entitlement with this set remains unverified. Server polling intervals and slow-down responses are honored; cancellation, denial, expiry and uncertain exchanges terminate the attempt rather than blindly replaying a potentially consumed authorization code.

Owned refresh/save/logout operations take a provider-specific OS file lock. A second concurrent caller reloads the rotated session instead of refreshing the old token. Cancellation before refresh claim preserves the saved session. Before dispatching refresh, the old refresh token is removed from the saved session; success atomically saves the validated replacement. Once claimed, that single exchange finishes within its own 30-second HTTP bound even if the foreground cancels, so a rotated credential is saved before rejecting the cancelled foreground request. This may delay cancellation up to that bound; it does not authorize subsequent inference or change a task's budget. Sign-out waits for the same lock, then removes the session; late refresh cannot resurrect it. An uncertain/rejected exchange cannot automatically replay the old token, but may require fresh sign-in after the remaining access credential expires. This conservative recovery tradeoff is explicit, not silent infinite retry. Account changes and identity/access-account disagreement are rejected. JWT payload decoding is metadata extraction from a fixed-origin TLS token response, **not signature verification or independent proof of account authorization**; the provider still validates the bearer on requests.

Nine OAuth functional checks are included in the 140-pass Windows library run, with one explicitly gated live diagnostic ignored: `.arun/oauth-core-library-20260927-final.log`. Tests exercise both device protocols, single-use exchange, pending/slow-down/denial/cancellation/expiry, unsafe UI/URLs, token/account validation, real concurrent refresh locking, durable non-replay, redirects and body bounds. The earlier eight-test run is `.arun/oauth-core-functional-20260927.log`; the ninth check and source-confirmed ChatGPT JSON refresh encoding were added afterward. ### Rejected-response accounting

Completed but invalid ChatGPT/Grok actions now retain their reported usage in `model.failed`, including interruption after a receipt. Custom OpenAI-compatible invalid actions or missing assistant text also preserve reported usage before parsing fails; absent failure usage is not replaced by a character estimate. Structural shape is retained without raw assistant text. No rejected action is applied.

The durable token projection, snapshot replay and trace totals include these failed receipts. Cached input remains part of total input, not a second charge or a discount from the budget. A subsequent attempt cannot bypass an exhausted token budget just because the previous action was rejected. Unknown failures remain explicitly unaccounted for comparisons; this change cannot reconstruct missing historical provider receipts or prove reduced actual token use by itself.

Schema 7 performs one transactional backfill from existing hot failures and validated archive segments, updates only affected snapshot accounting through the original snapshot sequence, and retains old snapshot artifacts/events/contracts. Archive segments are processed individually rather than materializing the whole conversation. Reopening does not double-charge; invalid ranges fail closed and roll back all projection/pointer/version changes. This migration is tested on disposable histories, not applied manually to frozen endurance data.

## Reviewed protocols

### Independent catalog transport groundwork

The direct adapter has authenticated, bounded GET requests for ChatGPT's `/backend-api/codex/models` and Grok's `/v1/models`. These share the model transport's account binding, Aegis identity, redirect refusal, cancellation, timeout and credential-safe error handling. ChatGPT's catalog query uses a separately declared reference catalog compatibility version (`0.156.0`); the originator, user agent and Aegis version header identify Aegis. Grok retains its explicitly separate transport-compatibility header. There is no native CLI or alternate-origin fallback.

Normalization retains only inference ID, sanitized display label, advertised reasoning levels and a default only when it is one of those levels. ChatGPT priority ordering and visibility are honored; Grok model/modelId/id and metadata reasoning formats are handled. Unknown levels, hidden/invalid/duplicate entries, upstream instructions, tools, permissions, API keys and routing configuration are not imported. Responses are limited to 8 MiB, at most 4096 incoming entries and 256 selectable models. Credential echoes are removed from recognized metadata fields before display truncation, including JSON-escaped tokens.
