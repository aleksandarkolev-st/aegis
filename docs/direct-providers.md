# Direct provider transition

The user requires Aegis to own its agent loop and use ChatGPT/Grok login without starting Codex or Grok Build. A smaller nested-CLI prompt is not the requested solution. Claude is pending at the user's request; custom OpenAI-compatible HTTP support remains required.

## Current state

Normal `src/model.rs` dispatch now uses Aegis-owned sign-in/refresh and `src/direct.rs`: ChatGPT Responses SSE or Grok chat completions. Native provider subprocesses, native usage estimation and automatic CLI installation/fallback have been removed from normal execution, login and catalog discovery. Custom OpenAI-compatible HTTP remains unchanged. Requests carry only Aegis instructions, bounded state and the six-action schema. Production provider destinations are fixed, not taken from workspace configuration. Fresh live authorization, remote model catalogs, remaining fixture migration and current packaging/installed verification are still unfinished.

Credential objects have no Debug or serialization implementation. Explicit saved-session reads are bounded to 1 MiB, regular-file checked, provider/account bound and read-only. They do not copy refresh tokens, mutate native credentials, select an arbitrary Grok account, or silently substitute an API key. They are not a replacement for Aegis-owned browser login, secure storage or refresh.

ChatGPT requires an explicit selected account. Grok's source-defined `X-XAI-Token-Auth` value selects its user-token authentication route; Aegis sends its own client identifier and User-Agent, not an official CLI User-Agent. HTTP 403 is a refusal, not an invitation to spoof another client or bypass access controls. Source-visible protocols do not guarantee third-party entitlement or stable hosted-service compatibility.

Only completed responses are accepted. Truncated/failed/refused responses, duplicate completions and unexpected native tool calls fail closed. Credentials echoed into assistant text are redacted before action parsing. Reported input/output/cache usage is preserved without subtracting bootstrap or cached tokens; missing usage stays unknown, never a zero-cost claim or character-based estimate. Redirects are disabled; connection, body size, interruption and timeout checks precede acceptance.

## Owned sign-in storage foundation

`src/auth_store.rs` adds bounded, provider-bound atomic storage at the user's `.aegis/auth` directory. Windows uses current-user DPAPI with provider-specific entropy, no machine-wide protection and no crypto prompt. Unix currently uses owner-only 0700 directories / 0600 files: **the Unix file contents are plaintext, not encrypted or keyring-backed**. Linked/reparse ancestors and credential files, malformed protection headers, oversized files and cross-provider copies are rejected. Expired sessions may be loaded for future refresh, but cannot produce request credentials. Errors do not include credential values; session structures have no Debug implementation.

At storage commit `45e59f5`, the foundation was not yet connected to OAuth/F4/normal dispatch; the newer routing follow-up below makes those connections. No real credential was stored or native credential changed during these checks. Windows library checks passed 131 with the explicit live diagnostic ignored: `.arun/auth-store-library-20260927-final.log`. Three real Docker isolation checks passed in `.arun/auth-store-docker-isolation-20260927.log`. Workspace file tools reject `.aegis` components; root Docker mounts mask root `.aegis`, and scoped mounts mask nested `.aegis`. Broad unscoped mounts do not yet mask all nested metadata, so this is not universal credential isolation for arbitrary home-directory workspaces.

The first library attempt exposed an `OsString`/`str` integration error; the corrected code converts names before the shared metadata check, without relaxing it. ## Owned device authentication and refresh core

`src/oauth.rs` implements two-phase device authentication for ChatGPT and Grok. The caller presents the verification link/code and controls polling/cancellation; this module does not open a browser, start a CLI or log the code. Fixed provider origins, no redirects, bounded declared/chunked JSON bodies, provider-specific protocol encoding and Aegis client identity are enforced. Grok requests a narrower six-scope set without remote conversation/workspace read/write scopes; real fresh-login entitlement with this set remains unverified. Server polling intervals and slow-down responses are honored; cancellation, denial, expiry and uncertain exchanges terminate the attempt rather than blindly replaying a potentially consumed authorization code.

Owned refresh/save/logout operations take a provider-specific OS file lock. A second concurrent caller reloads the rotated session instead of refreshing the old token. Before dispatching refresh, the old refresh token is removed from the saved session; success atomically saves the validated replacement. An uncertain/rejected attempt cannot automatically replay the old token, but may require fresh sign-in after the remaining access credential expires. This conservative recovery tradeoff is explicit, not silent infinite retry. Account changes and identity/access-account disagreement are rejected. JWT payload decoding is metadata extraction from a fixed-origin TLS token response, **not signature verification or independent proof of account authorization**; the provider still validates the bearer on requests.

Nine OAuth functional checks are included in the 140-pass Windows library run, with one explicitly gated live diagnostic ignored: `.arun/oauth-core-library-20260927-final.log`. Tests exercise both device protocols, single-use exchange, pending/slow-down/denial/cancellation/expiry, unsafe UI/URLs, token/account validation, real concurrent refresh locking, durable non-replay, redirects and body bounds. The earlier eight-test run is `.arun/oauth-core-functional-20260927.log`; the ninth check and source-confirmed ChatGPT JSON refresh encoding were added afterward. ## Normal routing and same-terminal sign-in

F4, guided onboarding and `arun login` now use `src/signin.rs`, not a provider executable. An owned worker presents a bounded verification code/link, polls in the background, honors Esc/Ctrl+C/Ctrl+D and joins on interface exit. The terminal renders its configured animated mascot without fake model-token/context counts. Windows opens the verified authorization link through ShellExecuteW with COM initialization, not another console; non-Windows currently provides the link rather than an automatic opener. Browser opening and actual fresh user approval are not yet visually/live verified. Sign-out removes only the selected Aegis credential. Claude explicitly reports pending; it cannot fall back to Claude Code.

New guided/advanced tasks freeze `provider_transport: aegis-direct-v1` and an explicit model. Old ChatGPT/Grok tasks lacking this marker fail readably rather than silently changing their immutable execution contract; saved chats remain inspectable. A reviewed continue-as-new migration UI is still needed. Refresh consumes the model request's remaining timeout via the same cancellation callback. Fresh independent remote catalog/advertised default/reasoning discovery and the explicit read-only saved-native-session connection UI still need implementation; a fresh account without caches currently requires an advertised manual model ID.
